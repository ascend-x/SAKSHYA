The Pitch in One Paragraph &
Why the Name Changed

The Core Pitch

An Intelligence Fusion Layer,
Not a Tool Replacement

SAKSHYA is an Intelligence Fusion layer, sitting above siloed proprietary forensic tools (Cellebrite, Griffeye, Nuix). Real investigators lose hours exporting reports from isolated tools and manually reading them side-by-side to connect dots: a motorcycle in a flagged video, a chat mention in a phone dump, a GPS point in a drone flight log. SAKSHYA's orchestrator reads these outputs and autonomously correlates what each tool sees in isolation.

The Precise Honest Claim: Only one component is agentic AI: a single LLM-driven reasoning loop that decides which deterministic tool to call next based on evolving findings. Hashing, face embedding, OCR, and financial tracing are deterministic tools called by the loop.

Etymology & Legal Anchor

Why "SAKSHYA"?

The working name ACPIA was functional but generic. SAKSHYA (साक्ष्य) is Sanskrit for evidence / testimony, chosen deliberately to echo the Bharatiya Sakshya Adhiniyam (BSA), 2023: India's evidence law replacing Section 65B of the Indian Evidence Act.

"This system doesn't just find evidence: it is architected around what makes evidence admissible in court."

01 / Legal & Procedural Grounding

Built for Section 63 BSA 2023,
Section 57 & POCSO Compliance

Courtroom admissibility dictates every architectural decision. SAKSHYA never generates unverified legal claims; it pre-fills certificates while ensuring the human investigator remains the certified authority.

Core Ethical & Legal Principle

"AI Accelerates. Humans Certify."

SAKSHYA never generates its own Section 63 certificate. AI points to evidence, computes cryptographic hashes, and pre-fills the certificate. A human Investigating Officer (IO) verifies findings on the cloned drive and signs personally.

Real-World Chain of Custody Workflow

01. Seizure & Isolation

Device immediately placed in a Faraday bag to block remote wipe signals and network manipulation.

02. Bit-by-Bit Imaging

A physical write-blocker creates a mathematically identical clone drive. The original device is never touched again.

03. Cryptographic Hashing

SHA-256 hash of the clone is generated immediately to prove immutability before any ingestion.

04. SAKSHYA Analysis

Only the verified clone drive is analyzed by SAKSHYA agents. Every parsed artifact references the clone hash.

Section 63 BSA 2023 Mandate

Mandatory Hash Certificates

Replaced Section 65B IEA on 1 July 2024. Statutory mandate requiring a dual-part certificate (Part A: IMEI/MAC hardware info; Part B: Expert SHA-256 validation) submitted to court for any electronic evidence.

Section 57 BSA 2023 Primary Evidence

Cache & System Graph Mapping

Section 57 (Explanations 4, 6, 7) establishes that files simultaneously stored across automated systems (including cache files) qualify as Primary Evidence. SAKSHYA maps full file timelines to determine if Sec 63 certificates can be bypassed.

POCSO & Trauma Protection

Automated Victim Face Masking

Displaying unredacted media is an offense under POCSO. SAKSHYA's Vision agent applies automatic blurring over victim faces and sensitive PII before reaching human reviewers, ensuring compliance and trauma relief.

04 / Correlation Specifics & Scale

Deterministic Math, Calibrated Gates &
Durable Checkpointing

7.1 Face Correlation Engine

512-Dim Cosine Vector Lookup

Photos are converted into fixed 512-dimension ArcFace vectors. Cosine distance math determines closeness: never generative guessing.

≥ 0.62 Cosine Sim: Auto-link candidate identity
0.45 – 0.62 Cosine Sim: Surface to human review queue
< 0.45 Cosine Sim: Reject link (No auto-merge)
7.2 Multi-Terabyte Resolution

Indexing, Not Context Window

A name in file #3 and file #48,000 is resolved by instant indexing, not reading 4TB into LLM context.

Parallel workers write structured facts into Neo4j graph + FAISS vector index. The LLM is called only on small, targeted, retrieved subgraphs.

8.1 Per-File Durable Checkpointing

Crash Recovery State Machine

Every file and extracted sub-object is a row in a SQLite/Postgres persistent job table.

queued ➔ processing (worker heartbeat every 15s) ➔ done
↓ No heartbeat for 90s (worker crashed / SIGKILL)
failed ➔ reclaimed & requeued automatically on worker restart
7.3 Vehicle Plate Lookup

YOLOv8 + VAHAN API

YOLOv8 plate detection ➔ OCR ➔ lookup. In production, calls authorized VAHAN endpoint. Mandatory reason-for-query field is logged on every call for audit compliance.

08 / Core Stack Rationale

Technology Stack & Architectural Rationale

★ Zero Proprietary Lock-In : 100% Offline Sovereignty
01. Agentic AI & Orchestration Offline Sovereignty

LangGraph + Local Ollama

Tech: LangGraph, Ollama, Qwen2-VL, Llama 3

WHY CHOSEN: Local quantized LLMs run 100% offline, guaranteeing zero evidence exfiltration to third-party cloud APIs. LangGraph provides stateful cyclic graphs required for autonomous ReAct reasoning loops over deterministic tools.
02. Fault Tolerance 100% Crash Proof

Durable Queue & Heartbeat Engine

Tech: SQLite / PostgreSQL, Heartbeat Reclaim Daemon

WHY CHOSEN: Forensic scans take 40+ hours. Per-file row state tracking (queued → processing → done/failed) with 90s heartbeat reclaim ensures a SIGKILL worker crash at hour 40 resumes instantly at task 48/54 without re-analyzing finished files.
03. Facial Biometrics

ArcFace & FAISS Index

Tech: InsightFace (ArcFace), FAISS Vector Store

WHY CHOSEN: Converts faces into deterministic 512-d vector math rather than generative guessing. FAISS enables sub-millisecond cosine distance lookups (≥0.62 auto-link, 0.45-0.62 human queue).
04. Graph Correlation

Neo4j Evidence Graph

Tech: Neo4j Community, NetworkX

WHY CHOSEN: Solves multi-terabyte cross-chunk resolution through indexing instead of context-window limits. Connects suspects, chat handles, vehicle plates, BTC wallets, and EXIF locations instantly.
05. Vision & OCR Ingestion

YOLOv8 & EasyOCR Engine

Tech: YOLOv8, EasyOCR, Tesseract, Apache Tika

WHY CHOSEN: Recursively unpacks compound media (PDFs with embedded photos). Built with open schemas matching enterprise tools (Cellebrite, Griffeye, VAHAN) for 1-line config swap-in.
